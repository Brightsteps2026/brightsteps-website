# Heading Hierarchy Fix — All 38 Pages

## What was wrong
Every page skipped from H1 straight to H3 (no H2 at all in most cases), and every page's footer used H5 for "Quick Links," "School Life," etc. — another skip. This was systemic, not the one spot the original audit called out.

## How I fixed it
This wasn't a find-and-replace job — your CSS styles headings by tag name inside specific components (`.photo-card h3`, `.program-card h4`, `.footer-grid h5`, `.prose h3`, `.contact-card h4`, `.cal-dates-block h3`, `.date-info h4`, `.life-card-body h3`), so every heading-level change needed a matching CSS update or the visual styling would break.

**Footer (all 38 pages):** "Quick Links," "School Life," "Connect," "Legal" etc. changed from H5 to H2. Since a page can repeat the same heading level without penalty (only *skipping* levels is the problem), making every footer heading H2 resolves the skip on every page regardless of how deep that page's own content nesting goes — no per-page judgment calls needed there. Updated `.footer-grid h5` → `.footer-grid h2` in the CSS to match.

**Main content, page by page:** I went through each of the 19 page templates individually and promoted the actual section headings (the ones that were incorrectly sitting at H3 with nothing at H2 above them) up to H2. A few examples:
- Simple flat pages (Privacy Policy, Terms of Use, Safeguarding, Cookie Notice, Careers, Uniform, Transportation, Mission & Vision) — all their section headings promoted H3 → H2.
- Pages with card grids (homepage programs, Academic Approach's age groups, Canteen, After School Activities) — I checked whether each card sat under its own labeled section (in which case the section heading became H2 and the cards correctly stayed one level below) or had no wrapping heading at all (in which case the cards themselves became H2, since they're the top-level content).
- The homepage's "program cards" (age groups) were H4 directly under an H2 with no H3 between — bumped to H3 to close that gap.
- The academic calendar's per-event titles are generated by `script.js`, not static HTML — updated that too (H4 → H3) so the dynamically inserted content doesn't reintroduce the skip.

Every one of these got a matching CSS selector update — mostly additive (e.g. `.photo-card h2, .photo-card h3` instead of a straight rename) so the same shared component class keeps working correctly on every page that uses it, even where the correct heading level differs page to page.

## Verification
Ran an automated check across all 38 pages after every change:
- Exactly one H1 per page — pass
- Zero duplicate IDs anywhere — pass
- Zero heading-level skips anywhere — pass
- No orphaned H4/H5 tags left in the HTML, no CSS rules left pointing at heading levels that no longer exist in the markup

## One more thing I noticed, didn't touch
Went through a lot of body copy while doing this and spotted hyphens in visible text — "inquiry-based," "well-being," "child-centred," "Third-party links" — scattered across several pages (careers.html, terms-of-use.html, and likely others). This is the same no-hyphens brand rule, just showing up in prose rather than headings. I didn't fix it now since it's a different, separately-scoped cleanup (needs a careful read through actual sentences, not a mechanical change), but flagging it as a finding for whenever you want to tackle it.
